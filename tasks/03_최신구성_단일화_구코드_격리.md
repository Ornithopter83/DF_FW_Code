# 작업 03

최신 구성 단일화와 구 코드 격리

## 목표

현재 사용하는 Main/Rod 구성만 활성 코드에 남기고 과거/비활성 분기는 빌드 외부 `deprecated/`에 보존한다.

## 현재 기준

- Main `Config.h`와 Rod `Common.h`에 다수의 Variant, test flag, `#if 0` 및 과거 주석 코드가 존재한다.
- 사용자는 과거 Variant로 돌아갈 계획이 없다.

## 관련 영역

- Main `Config.h`, `Common.h`, `DF_Main.ino`
- Rod `Common.h`, `DF_Rod.ino`
- 향후 `deprecated/main/`, `deprecated/rod/`

## 구현 원칙

- 먼저 deprecated 파일을 만든 뒤 활성 코드에서 제거한다.
- deprecated는 sketch 폴더 밖에 두며 빌드하지 않는다.
- C++11 이후 문법과 namespace를 사용하지 않는다.
- `#pragma once`, C++03 `enum`, `const`, `extern`을 사용한다.

## 세부 작업

### A. deprecated 보존 규약과 색인

- 경로, 파일 머리말, 출처 및 대체 코드 기록 형식을 만든다.

### B. Main 현재 설정 고정

- 작업 01에서 확정된 활성 분기를 별도 목록으로 만들고 한 기능군씩 단일화한다.

### C. Main 구 코드 격리와 전처리 제거

- 과거 interface, motor/hardware, test 및 disabled block을 기능별 deprecated 파일로 옮긴다.

### D. Rod 현재 설정 고정

- 최신 보드/입력/배터리/Encoder/IMU 구성을 단일 값으로 만든다.

### E. Rod 구 코드 격리와 전처리 제거

- 과거 보드와 비활성 기능을 deprecated로 옮기고 잘못된 조건 이름을 별도 결함으로 기록한다.

### F. C++03 호환 상수와 헤더 정리

- include guard는 `#pragma once`, 헤더 전역 정의는 `.cpp` 단일 정의로 정리한다.

### G. 금지 문법과 활성 전처리 검사 준비

- 프로젝트 코드에서 C++11 문법과 Variant 조건이 재도입되지 않았는지 찾는 검사 명령을 준비한다.

### H. 수동 빌드와 smoke 게이트

- Main과 Rod 각각 단일화 직후 Codex가 build를 실행한다.
- 주요 입출력과 통신 smoke test가 끝나기 전 다음 대규모 작업으로 넘어가지 않는다.

## 진행

잔여 작업 8개 (A, B, C, D, E, F, G, H)

## 변경 금지

- 활성 branch를 재설계하거나 프로토콜 값을 변경하지 않는다.
- deprecated 코드를 현재 코드에서 참조하지 않는다.

## 완료 조건

- 활성 코드에는 현재 제품 경로만 존재하고 제거된 코드는 출처와 함께 deprecated에 보존되어 있다.

## 시험 방법

- 각 기능군 제거 후 compile gate, Main/Rod 단일화 완료 후 사용자 수동 smoke test.
