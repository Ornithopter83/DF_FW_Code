# 작업 22

TM/Rod 릴 엔코더 소프트웨어 보정

## 목표

- TM에서 보정을 시작하고 완료할 수 있게 한다.
- 사용자가 기준 위치에서 릴을 한 바퀴 돌린 결과를 바탕으로 Rod 엔코더 출력이 확대되어야 하는 경우 한 바퀴당 20 정수 단계로 맞춘다. 출력 감소가 필요하면 역보정하지 않고 기존 환산을 유지한다.
- 보정값은 Main이 아니라 보정 대상 Rod 장치에 저장해 그 장치에 종속시킨다.

## 현재 기준

- Rod의 `Encoder::rotate()`는 홀센서 신호 변화마다 `count`를 올리고, `ENC_MUL_V3`, `ENC_DIV_V3`, `DIVISION_VAL`의 고정 비율로 `$14` 회전값을 만든다. 현재 상수는 원시 카운트 약 30개를 표시 20단계로 대응시킨다.
- Rod는 현재 `$14` 엔코더 상태를 Main으로 전송하고, Main은 TM에 전달한다. TM에는 릴 엔코더 상태 표시가 있지만 보정 명령 UI는 없다.
- TM↔Main 시리얼 `$15`는 기존 장치 제어 요청에 쓰이므로, 보정 명령 및 상태 프레임에는 비어 있는 `$37`을 사용한다.
- Rod 펌웨어는 SPIFFS를 마운트하며 `/addr.txt`와 `/imu.txt`에 Rod별 설정을 저장한다. 그러므로 보정값 저장 위치 후보는 Rod SPIFFS다.
- Main EEPROM이나 TM PC 설정 파일에만 보정값을 저장하면 릴/Rod를 다른 Main 또는 TM에 연결할 때 보정값이 따라가지 않으므로 이 작업의 요구를 충족하지 않는다.
- 현재 작업 범위의 장비 모델은 `릴 = Rod 보드`다. Rod 보드에 저장된 보정값을 해당 릴의 보정값으로 취급하며 별도 Reel ID는 추가하지 않는다.
- 릴의 내용물이 바뀌면 엔코더 회전 특성이 달라질 수 있으므로 TM에서 다시 보정해야 한다. 내용물 변경은 자동 감지하지 않고 사용자 재보정 절차로 처리한다.

## 변수 및 API 이름 제안

- `calibrationRawPulseCount`: 보정 시작 후 수집하는 원시 홀센서 변화 횟수.
- `calibratedPulsesPerRevolution`: 보정 완료 때 확정하는 한 바퀴당 원시 변화 횟수이며 Rod에 영속 저장한다.
- `calibrationActive`: 보정 수집 상태.
- `correctedStepCount`: 원시 카운트를 환산한 TM/기존 프로토콜 표시 단계.
- `beginCalibration()`, `completeCalibration()`, `applyCalibration()`, `cancelCalibration()`: Rod Encoder 보정 API.
- 이 값들은 Encoder 클래스 내부 상태로 두어 전역 심볼을 늘리지 않는다. 새 전역 프로토콜 심볼은 `DF_Protocol_` 접두어를 사용한다.

## 구현 원칙

- 보정 기준은 사용자가 표시해 둔 위치에서 시작해 같은 위치로 복귀하는 1회전이다. 홀센서에는 절대 원점 인덱스 입력이 없으므로 시작 버튼만으로 기계적 원점을 검출한다고 표현하지 않는다.
- 보정값 소유자는 Rod 보드이며, 제품 모델상 해당 보드를 릴 자체로 취급한다. 릴 내용물 변경 후에는 사용자가 보정을 다시 실행한다.
- 보정 중에는 기존 환산을 적용하지 않고 TM에 원시 센서 변화 횟수와 보정 상태를 표시한다. 시작 시 UI 표시를 `00`으로 초기화한다.
- 측정 완료 시 `C = calibrationRawPulseCount`를 적용 대기 상태로 보관하고, 사용자가 `적용`을 누르면 Rod SPIFFS에 저장한다. 표시 단계는 `(rawPulseCount * 20) / C`로 계산한다. `C` 자체를 저장하면 `double` 누적 오차 없이 20단계 회전 비율을 재현할 수 있다.
- 출력 배율 `20 / C`가 1보다 커서 한 원시 펄스가 여러 표시 단계를 요구할 때만 보정 출력을 적용한다. 각 원시 펄스에서 증가한 표시 단계 수를 정수로 누적하고, Rod 1ms 처리 주기마다 한 단계씩 순차 출력한다. `20 / C`가 1 이하이면 역보정하지 않고 기존 기본 환산을 유지한다.
- `C`가 0이거나 유효성 검사에 실패하면 기존 보정값을 유지한다. 취소·연결 해제·재부팅 중 미완료 보정도 기존 보정값을 덮어쓰지 않는다.
- 기본/보정값 없음/파일 손상 시에는 현재 상수 기반 환산을 유지하고 TM에 미보정 상태를 알린다.
- 보정값 파일은 Rod SPIFFS에 저장한다. 파일 누락·형식 버전 불일치·손상에 대한 기본값 복구를 구현하고, 실패한 저장을 성공으로 표시하지 않는다.
- 메시지 PID와 payload는 작업 22-A에서 확정했다. 기존 PID 및 payload 의미는 변경하지 않는다.
- 기존 Rod 엔코더 시험 경로가 `encoder.count`를 직접 변경하므로 시험 동작과 보정 상태가 충돌하지 않게 유지한다.
- 프로젝트 C++98/03 제한과 Main/Rod 공통 펌웨어 정책을 따른다.

## 세부 작업

### A. 보정 단위·릴 귀속·프로토콜 계약 확정

- 작업 범위 모델 `릴 = Rod 보드`와 내용물 변경 후 사용자 재보정 정책을 적용한다. 별도 Reel ID는 이 작업 범위에 포함하지 않는다.
- 보정 시작/진행/완료/취소/오류 메시지와 유효 범위를 확정한다.
- 사용자가 기준 위치에서 시작해 한 바퀴 후 완료하는 절차와 표시 단위를 확정한다.

- (완료: 2026-10-16) 릴을 Rod 보드에 귀속하고, 내용물 변경 후 사용자가 재보정하는 정책을 확정했다.
- (완료: 2026-10-16) Main→Rod PID 35 동작(`S` 시작, `C` 측정 완료, `A` 적용/저장, `X` 취소, `Q` 조회)과 Rod→Main PID 36 상태(`상태,보정유효,보정중원시카운트,저장된회전당원시카운트)를 공유 프로토콜에 추가했다. 상태 코드는 `0` 대기, `1` 보정 중, `2` 저장 완료, `3` 무효 카운트, `4` 저장 오류, `5` Rod 미연결, `6` 잘못된 동작, `7` 적용 대기다.
- (완료: 2026-10-16) 보정 중 원시 카운트 변경마다 상태를 보내고, 성공 응답은 보정된 회전당 원시 카운트를 포함하는 계약으로 정의했다. 기존 PID 18 엔코더 payload는 그대로 둔다.
- 확인 근거: `DFProtocol.h/.cpp`와 `docs/protocol/DF_PROTOCOL_CONTRACT.md`에 PID, action/state 상수 및 예시 프레임을 반영했다. 빌드·테스트는 실행하지 않았다.

### B. Rod 보정 상태·환산·영속 저장 구현

- 원시 변화 횟수를 측정해 `calibratedPulsesPerRevolution`을 산출하고 Rod SPIFFS에 저장·복구한다.
- 저장 성공 전에는 새 값을 적용 완료로 보고하지 않는다. 실패 시 이전 보정값을 보존한다.
- 적용 환산으로 한 바퀴가 정확히 20단계가 되게 하고, 기본값 복구와 미완료 취소를 처리한다.

- (완료: 2026-10-16) Rod 엔코더에 보정 상태와 시작/완료/취소/조회 API를 추가했다. 보정 중에는 `$14` 정상 환산 출력을 멈추고 PID 36으로 raw count를 보고하며, 시작 및 종료 시 기존 표시를 `000`으로 초기화한다.
- (완료: 2026-10-16) 측정 완료는 상태 `7` 적용 대기까지만 수행한다. TM에서 `적용`을 누르면 raw pulse count를 `/encoder_calibration.txt`에 기록·재확인한 뒤 적용한다. `취소`는 적용 대기값을 버린다. 임시/백업 파일을 이용해 기존값을 보존하고, 재부팅 시 파일을 읽어 Rod별 보정값을 복구한다. 파일 누락은 기존 기본 환산(30 pulse/rev)을 쓰며, 손상·쓰기 오류는 기본/이전 값과 오류 상태를 유지한다.
- (완료: 2026-10-16) 표시 환산은 정수식 `(rawCount * 20) / calibratedPulsesPerRevolution`을 사용한다. 유효 카운트 범위는 1~100000이다.
- (완료: 2026-10-16) 추가 사용자 지시에 따라 확대 보정(`C < 20`)에서만 출력한다. 입력 한 번에 여러 표시 단계가 생기면 정수 출력 대기열에서 1ms마다 한 단계씩 순차 전송한다. 축소가 필요한 경우(`C >= 20`)에는 보정하지 않고 기존 30 pulse/rev 기본 환산을 유지한다.
- 확인 근거: `firmware/DF_Rod/src/Encoder.h/.cpp`, `DF_Rod_Communication.cpp`, `DF_Rod_Application.cpp`의 소스 변경 확인. 빌드·테스트는 실행하지 않았다.

### C. Main 중계 및 TM 보정 UI 구현

- Main은 TM 보정 명령을 연결된 Rod에 전달하고 Rod 상태 응답을 TM에 중계한다.
- TM은 시작/완료/취소 버튼, 원시 변화 횟수, 연결·저장·오류 상태를 표시한다.
- Rod 미연결, 보정 중 연결 해제, 무효 카운트 및 저장 실패를 사용자에게 구분해 표시한다.

- (완료: 2026-10-16) Main은 TM 전용 `$37S/C/X/Q%` 명령을 연결되고 깨어 있는 Rod로 PID 35 전송하고, Rod PID 36 상태를 `$37`로 중계한다. 미연결·등록 중·sleep 및 잘못된 동작은 별도 상태로 응답한다. 기존 `$15` 장치 제어 요청과의 충돌을 피했다.
- (완료: 2026-10-16) TM 릴 화면을 상태별 버튼으로 동적으로 구성했다. 대기에는 `엔코더 보정` 하나만 보이고, 시작 후에는 `보정 완료`와 `취소`, 측정 완료 후에는 `적용`과 `취소`가 보인다. 원시 회전 카운트와 보정 상태를 표시하고, 시작 전 기준 위치와 같은 방향 한 바퀴 절차를 안내한다. 릴 연결 전이 및 초기 연결 완료 시 Rod 보정 상태를 조회한다.
- 확인 근거: `firmware/DF_Main/src/DF_Main_State.cpp/.h`, `DF_Main_Scheduler.cpp`, `testModule/DeviceProtocol.cs`, `testModule/MainForm.cs`, `docs/protocol/DF_PROTOCOL_CONTRACT.md` 소스/계약 확인. 빌드·테스트·실물 회전은 실행하지 않았다.

## 변경 금지

- Rod가 아닌 Main 또는 TM PC에만 보정값을 저장해 릴 종속 요구를 약화하지 않는다.
- 기존 엔코더 프로토콜 payload, 릴 버튼/모터 동작 또는 Main 엔코더 동작을 의도 없이 변경하지 않는다.
- 보정 중인 미확정 카운트로 기존 운용 보정값을 덮어쓰지 않는다.
- 저장 실패·미연결·무효 카운트를 보정 성공으로 표시하지 않는다.

## 완료 조건

- Rod 보드(이 작업 범위에서 해당 릴로 취급)의 보정값 귀속이 구현되고, 같은 Rod를 다른 Main/TM에 연결해도 값이 유지된다.
- 릴 내용물 변경 후 TM에서 다시 보정을 실행할 수 있으며 새 보정값이 기존 값을 교체한다.
- 보정 과정에서 `C < 20`이면 기준 회전 1회에 20개의 정수 단계가 순차 출력되고 TM에 상태와 결과가 표시된다. `C >= 20`이면 기존 환산을 유지한다.
- 보정값 없음/손상/취소/저장 실패 시 기존 기본 환산 또는 이전 정상 보정값으로 안전하게 동작한다.
- 별도 승인 후 빌드·프로토콜 검증 결과가 기록된다. 실제 릴 시험은 사용자가 수행한다.

## 시험 방법

- Rod에 보정값이 없을 때 기본 상수 환산 유지.
- `C < 20`인 경우 보정 시작 후 표시 `00`, raw count 증가, 적용 후 한 회전 20개의 정수 출력 확인.
- `C >= 20`인 경우 보정값이 저장되어도 기존 30 pulse/rev 환산이 유지되는지 확인.
- 저장 후 전원 재시작 및 다른 Main/TM 연결 후 동일 보정값 복구 확인.
- 취소, `C=0`, 비정상 카운트, 파일 손상, SPIFFS 쓰기 실패, 보정 중 Rod 연결 해제 확인.
- 실제 릴 기준 위치 복귀와 단계 정합은 사용자 수동 확인.
