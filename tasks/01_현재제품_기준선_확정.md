# 작업 01

현재 제품 기준선 확정

## 목표

`Vm1.0.9.0` Main과 `Vr1.0.1.0` Rod의 소스, 하드웨어 구성, Arduino 참조, 기존 산출물 및 장비 동작을 이후 모든 변경의 비교 기준으로 확정한다.

## 현재 기준

- 원본 소스와 `.bin/.elf/.map` 산출물이 존재한다.
- `.map`에서 Arduino-ESP32 Core 2.0.17이 확인된다.
- 정확한 FQBN menu option과 외부 라이브러리 버전은 미확정이다.
- 현재 PC PATH에 Arduino CLI가 없다.

## 관련 영역

- `Vm1.0.9.0/`, `Vr1.0.1.0/`
- `docs/build/ARDUINO_REFERENCE_AUDIT.md`
- 향후 `legacy/`, `docs/hardware/`, `docs/releases/`

## 구현 원칙

- 이 작업에서는 펌웨어 로직을 변경하지 않는다.
- 전체 원본과 제거 코드 보존 정책을 혼동하지 않는다.
- 장비 식별 정보와 COM 포트는 추적 문서에 고정하지 않는다.

## 세부 작업

### A. 저장소와 원본 기준선 목록 확정

- 현재 파일 수, 줄 수, 산출물 해시와 원본 경로를 manifest로 기록한다.
- `legacy/` 복사 또는 이동 방식을 결정하되 원본을 손상하지 않는다.

### B. 현재 Main 하드웨어 구성 확정

- 실제 사용 보드, 모터, 센서, 인터페이스와 활성 설정을 코드/장비 기준으로 대조한다.

### C. 현재 Rod 하드웨어 구성 확정

- 최신 Rod 보드, Button V2, Battery 800 V2, Encoder V3 등 코드 추정값을 실제 장비와 대조한다.

### D. Arduino 참조와 외부 라이브러리 확정

- CLI, FQBN options, Core 2.0.17, ESP32Servo 및 Kalman의 정확한 출처와 버전을 기록한다.

### E. 기존 산출물 기준값 확정

- Main/Rod firmware size와 SHA-256, partition 및 upload option을 release manifest로 기록한다.

### F. 수동 기준 빌드 게이트

- 환경 준비 후 Codex가 Main/Rod 빌드 명령과 필요한 결과를 제시한다.
- 사용자가 두 빌드를 수동 실행하고 결과를 전달한다.

### G. 수동 기준 장비 게이트

- 사용자가 기존 펌웨어의 flash 및 기본 Main–Rod smoke test를 수행한다.
- 장비가 필요한 항목은 결과를 받을 때까지 보류한다.

## 진행

잔여 작업 7개 (A, B, C, D, E, F, G)

## 변경 금지

- 기준 원본 소스와 바이너리를 덮어쓰지 않는다.
- 검증되지 않은 Arduino Core 또는 외부 라이브러리를 기준 버전으로 선언하지 않는다.

## 완료 조건

- 현재 제품 한 쌍을 재현하는 데 필요한 소스, 하드웨어, 빌드 참조 및 수동 동작 결과가 문서화되어 있다.

## 시험 방법

- F까지는 사용자 수동 clean build 결과가 필요하다.
- G는 실제 Main/Rod 장비와 사용자의 수동 시험이 필요하다.

## 결과

- 2026-08-27 작업 01-D 부분 점검: 프로젝트 로컬 Arduino CLI 1.5.2-rc.1 실행 및 ESP32Servo 1.1.2 인식을 확인했다.
- 2026-08-27 작업 01-D 부분 점검: `toolchain/arduino-data`에 ESP32 Core 2.0.17과 요구 compiler/tools를 설치했다. `esp32:esp32:esp32s3` board definition과 Core/ESP32Servo 필수 헤더의 존재를 확인했으며 빌드는 수행하지 않았다.
- 2026-08-27 불필요 의존성 판정: Rod의 `Kalman.h`는 실제 객체 코드가 `#if 0` 내부에만 있어 현재 제품에서 사용되지 않는다. Kalman library는 설치하지 않고 활성 코드 정리 시 include와 죽은 코드를 제거한다.
- 작업 01-D는 정확한 FQBN menu options가 남아 있어 완료 처리하지 않았다.
