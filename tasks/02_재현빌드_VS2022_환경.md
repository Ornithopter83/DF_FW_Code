# 작업 02

Main/Rod 재현 빌드와 VS2022 환경

## 목표

Arduino IDE를 열지 않고 Main과 Rod를 각각 또는 함께 빌드할 수 있는 명령과 VS2022 실행 경로를 구축한다.

## 현재 기준

- 기존 upload batch는 있으나 source compile script는 없다.
- 프로젝트 로컬 Arduino CLI 1.5.2-rc.1, ESP32 Core 2.0.17, ESP32Servo 1.1.2가 설치되어 있다.
- Main/Rod 공통 전체 FQBN은 `PROJECT_COMMANDS.md`에 확정되어 있다.
- Visual Studio Professional 2022 17.14가 설치되어 있다.

## 관련 영역

- 향후 `tools/`, `docs/build/`, VS2022 solution 또는 Open Folder 설정

## 구현 원칙

- MSVC가 펌웨어를 직접 컴파일하지 않는다.
- Arduino CLI가 실제 compiler driver다.
- COM 포트 등 PC별 값은 Git에서 제외한 로컬 설정으로 둔다.

## 세부 작업

### A. Arduino CLI 환경 구성 문서 (완료: 2026-08-27)

- 확정 버전, Core URL, Core 2.0.17 및 외부 라이브러리 준비 절차를 기록한다.

### B. Main build script (완료: 2026-08-27)

- 입력, 출력 경로, FQBN options 및 실패 code를 명시한다.

### C. Rod build script (완료: 2026-08-27)

- Main과 독립적인 sketch와 artifact 경로를 사용한다.

### D. 통합 build 및 artifact 확인 script (완료: 2026-08-27)

- Main/Rod를 순차 실행하고 결과 파일과 크기를 요약한다.

### E. VS2022 연결 (완료: 2026-08-27)

- Open Folder 또는 NMake 방식으로 build 명령을 연결하고 IntelliSense include 경로를 문서화한다.

### F. 재현 빌드 게이트 (완료: 2026-08-27)

- Codex가 VS2022 MSBuild로 clean Main/Rod build를 직접 수행하고 산출물을 확인한다.

### G. VS2022 IntelliSense Arduino 참조 복구 (완료: 2026-08-27)

- Main/Rod가 공통 ESP32-S3 Core/SDK/library include와 전처리 정의를 사용하도록 구성한다.
- Arduino builder가 자동 삽입하는 `Arduino.h`를 VS IntelliSense forced include로 재현한다.

### H. 버전별 배포 산출물 관리 (완료: 2026-08-27)

- 중간 산출물은 `artifacts/`에 유지하고 플래시용 파일만 `bin/<configuration>/<platform>/<version>/`에 배포한다.
- Main/Rod 버전 폴더마다 application, bootloader, partitions, `boot_app0.bin`의 4개 파일만 둔다.
- 현재 배포 폴더 버전은 `tools/firmware-versions.cmd` 한 곳에서 관리한다.

## G 표시 오류 보완 (설정·빌드 확인: 2026-08-31)

- 사용자 첨부 화면의 `IRAM_ATTR` E0070, `vPortEnterCritical` E0020 및 후속 E0065에 대해 공통 원인 후보인 GCC `__attribute__` 해석을 보정했다. `vs/DF_IntelliSense.h`를 `Arduino.h`보다 먼저 강제 포함하고 MSVC IntelliSense 분석에서만 속성을 생략한다. 실제 펌웨어/SDK 소스와 NMake build 명령은 변경하지 않았다.
- Main/Rod Debug/Release x64 네 구성의 MSBuild 속성 평가에서 강제 포함 순서와 파일 존재를 확인했다.
- `tools/build-all.cmd Release x64` compile/link exit 0. Main application 884,857 bytes/bin 885,216 bytes, Rod application 766,713 bytes/bin 767,072 bytes, 대상별 배포 파일 4개. 로그: `artifacts/intellisense-validation/build-all.log`.
- `xtensa-esp32s3-elf-objdump -t -C`로 Main ELF의 `ISR_onTimerHandler()`가 `.iram0.text`에 유지됨을 확인했다. Main/Rod sketch compiler 의존성에 `DF_IntelliSense.h`가 없는 것을 확인했다.
- VS IDE에서 재로드/재분석 후 세 표시 오류가 사라지는지는 사용자 확인 대기다. 화면 오류 전체 해결로 기록하지 않는다. flash/장비 시험 및 작업 10-H는 수행하지 않았다.
