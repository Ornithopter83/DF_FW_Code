# 작업 04

Main/Rod 공유 프로토콜 계약

## 목표

현재 Main과 Rod가 사용하는 ESP-NOW/UART 메시지의 방향, PID, payload 및 제한을 한 곳에서 정의하고 양쪽이 같은 계약을 사용하게 한다.

## 현재 기준

- PID와 문자열 상수가 양쪽 `Common.h` 및 `.ino`에 중복되어 있다.
- 송신은 주로 `pid + payload` 문자열이며 최대 128바이트 고정 버퍼를 사용한다.

## 관련 영역

- Main/Rod `Common.h`, `ENow.cpp/.h`, 수신 handler
- 향후 `docs/protocol/`, `libraries/DFProtocol/`, `tests/protocol/`

## 구현 원칙

- 과거 버전 호환을 목표로 하지 않고 현재 Main/Rod 한 쌍만 검증한다.
- protocol 형식 변경이 아니라 중복 정의 제거가 1차 목표다.
- C 스타일 API, 고정 버퍼, 명시적 길이, 고유 접두어를 사용한다.

## 세부 작업

### A. 메시지 전수 목록

- 방향, PID, payload 형식, 길이, 응답 및 timeout을 조사한다.

### B. Golden fixture와 계약 문서

- 현재 코드가 생성/수신하는 대표 byte 문자열을 변경 금지 기준으로 기록한다.

### C. C++03 호환 DFProtocol 인터페이스

- `typedef struct`, `typedef enum` 또는 익명 enum, `DF_Protocol_` 함수로 구성한다.

### D. Host 호환 검사 준비

- encode/decode, 잘린 입력, 초과 길이, 미등록 PID 사례를 장비 없이 확인할 수 있게 준비한다.

### E. Main의 공유 계약 적용

- 기존 결과 문자열을 유지하면서 중복 상수와 parser를 교체한다.

### F. Rod의 공유 계약 적용

- Main과 동일한 계약을 사용하도록 교체한다.

### G. 수동 protocol/Main–Rod 게이트

- 사용자가 준비된 호환 검사와 실제 Main–Rod 통신 시험을 수행한다.

## 진행

잔여 작업 7개 (A, B, C, D, E, F, G)

## 변경 금지

- PID 재번호화, payload 재설계, delimiter 변경을 함께 수행하지 않는다.

## 완료 조건

- 현재 Main/Rod 프로토콜 정의가 한 곳에 있고 대표 메시지 호환 결과가 수동 확인되었다.

## 시험 방법

- G에서 사용자 수동 host 검사와 실제 장비 통신 결과가 필요하다.
