# 작업 16 — 보드 AP/TCP 및 BoardWifiConnector

## 승인과 범위

2026-10-02 사용자 요청 1/2 및 후속 승인: Main의 무선 초기화·전원버튼·게임 연결 판정·종료 처리와 PC 구성 조사 및 구현. 두 구현 항목은 명시적 묶음 요청이다. 빌드·테스트·반복 검증·플래시·설치·Windows 종료 실행·commit/push는 승인되지 않았다.

## 작업 단위

- A: AP/TCP·시리얼 우선 종료 중계 구현 (완료: 2026-10-02).
- B: 단일 인스턴스·트레이 PC 프로그램, INI 및 최초 등록·개발 설정 구현 (완료: 2026-10-02).
- C: Main 및 Connector 자체 포함 단일 EXE 빌드/게시 확인 (완료: 2026-10-02).

## 설계 기준

- ESP32-S3 / Core 2.0.17, 기존 ESP-NOW 채널 1 및 STA 인터페이스 유지.
- AP와 TCP 통신은 항상 유지하고 실제 종료 요청만 게임 시리얼 우선으로 선택한다.
- 기존 게임 응답 후 USB5V 하강/전원 차단 상태 흐름 및 2분 제한은 보존한다.
- AP 비밀번호/접속 토큰은 보드에서 생성해 NVS에 보존한다. USB 최초 등록에서만 PC에 전달하며 로그에 기록하지 않는다.
- PC는 Windows Wi-Fi 프로필과 사용자 DPAPI로 보호된 접속 토큰을 사용한다. 고정 connection.ini의 대상만 접속한다.
- 일반 창 없이 트레이, 미연결 회색/연결 중 노랑/실패 빨강/정상 녹색. 최초 등록은 트레이 메뉴에서 명시적으로 실행한다.
- 트레이 자동 시작은 사용자 로그온 기준이다. 사용자는 비동기 질문에 로그온 후 동작이면 충분하다고 응답했다. 별도 서비스는 제외한다.

## 실제 변경과 근거

- A: DF_Main_BoardWifi.h/.cpp 신설. NVS에서 생성/보존한 기기별 WPA2 비밀번호·토큰, AP 채널 1, 단일 인증 TCP 클라이언트, 생존 신호, 입력 길이 제한과 비차단 송신, 세션/요청 번호 기반 종료 요청/ACK 처리.
- ENow는 WIFI_AP_STA로 변경하고 Application에 초기화·poll을 연결했다. Scheduler의 USB 최초 등록 명령은 정상 시리얼 명령 카운트/로그 앞에서 처리한다.
- Diagnostics는 기존 시리얼 전원 요청 지점에서 새 경로 선택 API를 호출한다. 게임 우선/연결 상실 시 Wi-Fi 전환, 기존 응답/USB5V/2분 차단 상태는 유지한다.
- 변경 전 Main 네 파일을 deprecated/main/board-wifi-before-20261002에 .txt로 보존했다.
- B: 루트 BoardWifiConnector에 WinForms WinExe, Global Mutex, 트레이 네 상태, 고정 EXE 폴더 INI, 사용자 Wi-Fi 프로필, DPAPI 토큰, USB 등록, 자동 재연결, 정상 Windows 종료 후 ACK, 중복 요청 방지, 명시적 메뉴 자동 시작 등록/해제 구현.
- 독립 VS2022 솔루션·VS Code workspace·복원/빌드/게시 스크립트 및 README를 작성했다. 출력은 루트 bin/BoardWifiConnector 하위 상대 경로다.
- 비밀정보 원문은 코드·문서·로그에 넣지 않았다. 실제 자격 정보는 프로그램 최초 등록에서만 생성/저장한다. INI/credential.dat는 Git 제외다.
- 확인 근거는 승인된 관련 소스 조회와 코드 작성 도구의 완료 반환이다. 빌드·정적 검사·통신/GUI 테스트를 수행한 근거는 아니다.

## 미실행과 사용자 설정

NuGet 복원/잠금 파일 생성, Main/Connector 빌드, 정적/실행/장비 시험, EXE 생성, 설치, 등록/플래시, 실제 Windows 종료, commit/push 모두 미실행이다. 16-C는 새 승인 후 실행한다. 기존 작업 12/15의 빌드를 함께 실행하지 않는다.

connection.example.ini의 AllowWindowsShutdown은 false로 시작한다. 사용자 최초 등록 후 true로 변경하고 재연결하면 실제 종료 요청을 사용한다. false는 성공 ACK를 보내지 않으며, 전원버튼 입력 시 기존 보드 2분 강제 차단 조건이 그대로 적용될 수 있다.

게임 실행 시 호출하는 외부 게임 정리 코드는 이 저장소에 없다. 게임이 없는 Wi-Fi 경로에서는 Windows 정상 종료를 요청하고 기존 보드 응답 및 전원 처리 상태에 합류한다.
